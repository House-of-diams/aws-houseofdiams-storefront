# HOD storefront AWS UAT deployment handoff

Updated 2026-10-11 after the user-authorized local F9 connection cleanup. The storefront now uses RDS for data and CloudFront/S3 for owned media. Its AWS build/runtime does not need Supabase, Cloudflare/R2, Vercel or F2 read-selection ENV settings. This is a UAT configuration handoff; production release remains pending.

Use [aws-uat-env.template](./aws-uat-env.template) for the credential-free inventory. The populated testing file is outside the repository at `D:\Main Hod\private-devops-handoff\hod-aws-uat.env`. Do not put that file in the public GitHub repository. Available testing credentials are already copied into it; the missing Keycloak confidential-client secret and shared Redis URL are clearly marked. No credential values are included in this document.

1. Deploy the complete Next.js server/API application to AWS. Provide `NEXT_PUBLIC_*` settings during the build and at runtime. Set the UAT website and authentication URLs shown in the template.
2. Inject the private RDS URL for `hod_app` on `hod_staging` into the server process from the deployment secret store. Mount the public AWS RDS us-east-1 CA bundle at the configured Linux path. Omit `DB_TLS_EXPECTED_HOST` on AWS; it belongs only to the local SSM tunnel. Verify private network access and `/api/readiness/db`.
3. Set `NEXT_PUBLIC_MEDIA_CDN_BASE_URL=https://media.houseofdiams.com`. Confirm CloudFront can read the private S3 objects and that uploads, content and historical URL translations work. The two previously accepted missing SVG objects remain an earlier exception.
4. Supply the `hod-storefront` confidential-client secret from the `hod-customers` Keycloak realm. Configure callback `https://uat.houseofdiams.com/api/customer-auth/callback`, logout `https://uat.houseofdiams.com/` and exact web origin. Google provider credentials belong in Keycloak. Keep customer authentication, F7 payment writes and F8 reconciliation flags OFF initially.
5. Supply shared Redis and verify rate limits across instances. The existing approved Upstash integration remains compatible. Standard AWS Redis with password authentication is supported by the current client; this task did not provision or switch Redis infrastructure.
6. Verify storefront SMTP and its sender. If AWS-only email hosting is required, supply SES SMTP credentials; the current SMTP code supports that without a provider rewrite. Existing testing SMTP credentials remain in the private handoff. These differ from Keycloak realm SMTP.
7. Replace the failing Fixer key before testing non-USD checkout. USD quote checks do not establish INR/other-currency payment readiness. Keep Razorpay test credentials and verify the actual UAT webhook secret against the dashboard configuration.
8. Confirm the intended maintenance setting before browser UAT. Do not remove checkout placement guards or enable payment/reconciliation flags simply to make a test pass. Their release review, real Keycloak/Razorpay flows, AWS scheduler, timeout/lease behavior, monitoring and operator review remain required.

Razorpay, Fixer and optional Google services remain external business integrations. AWS data/media hosting does not replace those services. Supabase and Cloudflare credentials are absent from the storefront handoff. Historical public media hostnames in source are only a URL-to-CDN translation registry and trigger no calls to those hosts.
