## Authorization decision and preflight

The 53 affected tables with `ALL/SELECT TO PUBLIC USING is_admin()` are narrowed to `authenticated` (54 policies, because `navbar_sections` has two). This is a **temporary staging compatibility bridge**, not final AWS/Keycloak authorization. It preserves the existing `is_admin()` expression for legacy Supabase-authenticated admin sessions. DevOps must confirm current admin access before applying; a future separately reviewed admin-role/server-side authorization migration must replace this bridge. No `hod_app` membership in `authenticated` is allowed.

Eleven existing `SELECT TO anon,authenticated` policies add only `hod_app`; their predicates and prior roles remain unchanged. Twenty-nine previously policy-free tables receive `SELECT TO hod_app` policies with predicates mapped below to current query/output behavior. Four tables require no policy change. One extra, narrowly scoped hidden `bespoke` navbar read preserves an existing lookup. No existing public SELECT predicate is rewritten.

The forward transaction aborts unless all 94 in-scope F2 tables exist with RLS enabled, FORCE RLS off, `hod_app` SELECT grants, and the **entire in-scope** policy set matches the supplied export plus the already-applied F2-A role changes. It checks `hod_app` has no superuser/BYPASSRLS/admin membership/auth-schema USAGE, verifies the legacy `is_admin()` owner/body, predicate columns, and parent FKs. A failure means **stop and revise the package**, not bypass the guard. The user supplied read-only column/FK, grant, role, and policy exports; the remaining approval boundary is response/visibility parity for active read paths. No RDS query or SQL execution was done by Codex for this request.

The supplied export is a **policy** snapshot, not a full GRANT snapshot. The preflight strictly requires SELECT on every F2 table and leaves all grants unchanged, but it cannot compare unrelated INSERT/UPDATE/DELETE grants to an unavailable audited baseline. DevOps should run the read-only grant inventory in the verification file **before approval** and review any unexpected write privilege. Do not treat the package as already approved on that point.
